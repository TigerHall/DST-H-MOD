# 切斯特月眼轮盘 —— 月眼解锁功能方案（最终评估版 v2）

## 需求（已确认全部决策）

1. **服务端权威存档**：解锁状态跟世界存档走（按 userid），重启/重进保持
2. **功能锁**：未解锁的月眼**不能打开对应空间**
3. **解锁判定**：手持**或**背包里有对应月眼即可
4. **未解锁点击提示**：人物说话 = 背包图标 + 物品名（中英文适配）+ 灯泡图标
5. **新增配置项**：解锁机制可单独开关——关掉时**全部月眼直接可用、全彩色、无灰黑、无扫描**（=当前行为）
6. **修正（用户最终确认）**：
   - 持有检测**只做一次**（服务端权威验证，不搞客户端+服务端双重）
   - 说话提示 = 背包图标 + **prefab 名字符串**（GetDisplayName 自动中英文）+ 灯泡图标
   - 配置中途关掉=全解锁，但**不删解锁存档**；再打开时套用之前的解锁记录

## 详细设计

### A. 新增配置项

```lua
moon_eye_unlock   -- "月眼解锁机制"，默认 true
```
- **true（默认）**：启用解锁——未解锁月眼灰黑 + 不能开空间 + 手持/背包扫描解锁
- **false**：完全跳过解锁逻辑——所有月眼彩色可点可开（=升级前行为），不读写解锁存档

> 注意：配置只控制"是否启用解锁"，不影响空间本身。关掉时 `TogglePocketDimensionChest` 不加锁。

### B. 服务端数据结构与存档

- 复用项目现有范式，新增：
  - `UNLOCK_DATA = {}` —— `[userid][container_key] = true`
  - `UNLOCK_SAVE_KEY = "hslot_mooneye_unlocked"`
  - `SerializeUnlock` / `DeserializeUnlock` / `SaveUnlockData` / `LoadUnlockData`（照抄 REVEALED 那套，格式 `"uid=k1,k2|uid2=k1"`）
- 世界初始化时 `LoadUnlockData()`
- 玩家解锁成功 → `UNLOCK_DATA[uid][key] = true` → `SaveUnlockData()`

### C. 服务端→客户端同步（netvar）

- `AddPrefabPostInit("player_classified", ...)`：挂 `inst._hslot_unlock = net_string(inst.GUID, "_hslot_unlock", "hslotUnlockDirty")`
- 服务端在玩家进入/解锁变更时 `classified._hslot_unlock:set(序列化后的已解锁 key 串)`
- 客户端监听 dirty 事件 → 解析 → 刷新 UI 灰黑/彩色

### D. 功能锁（关键，一处拦截所有路径）

在 `TogglePocketDimensionChest(viewer, container_key)` 开头加：

```
if config.moon_eye_unlock and not IsUnlocked(viewer.userid, container_key) then
    -- 人物说话提示：背包图标 + 物品显示名 + 灯泡图标
    local prefab = KEY_TO_MOONEYE_PREFAB[container_key]   -- 见下表
    local name = SpawnPrefab(prefab):GetDisplayName()      -- 中英文自动适配
    viewer.components.talker:Say(BACKPACK_ICON .. " " .. name .. " " .. BULB_ICON)
    return   -- 不打开空间
end
```

**container_key → 月眼 prefab 对照**（GEMS 表的 tex 名即 prefab 名）：
| key | prefab | 显示名（中/英）|
|---|---|---|
| hslot | bluemooneye | 蓝月眼 / Blue Moon Eye |
| rabbitkinghorn | greenmooneye | 绿月眼 / Green Moon Eye |
| orange_fish | orangemooneye | 橙月眼 / Orange Moon Eye |
| yellow_fish | yellowmooneye | 黄月眼 / Yellow Moon Eye |
| purple_fish | purplemooneye | 紫月眼 / Purple Moon Eye |
| shadow | redmooneye | 红月眼 / Red Moon Eye |

> 用 `GetDisplayName()` 而非硬编码，天然适配中英文；临时 SpawnPrefab 后 Remove（项目现有做法 modmain.lua:251-255）。

### E. 解锁流程（客户端发起 → 服务端验证）

```
客户端：左键点未解锁的灰黑月眼 i
  → 发 RPC "hslot_pocket.unlock" (key)
  → 服务端：验证 player 持有对应月眼（手持 or 背包遍历）
      ├─ 持有 → UNLOCK_DATA[uid][key]=true + 存盘 + 更新 netvar + 说话提示（可加"已解锁"）
      └─ 未持有 → 服务端说话提示（背包图标+物品名+灯泡图标）
```

- **服务端验证持有**：防作弊（不能只信客户端）。用 `player.components.inventory:HasItemWithTag` 不适用（月眼无专属 tag），改用遍历 `GetItemInSlot` + `GetActiveItem` 比对 `inst.prefab`
- 即使客户端只认"手持或背包"判定能否点击，服务端也要再验一次

### F. 客户端 UI 视觉状态机

| 状态（config 开） | 本体 tint | glow | hover 放大/呼吸 | 点击行为 |
|---|---|---|---|---|
| 未解锁 | 灰黑 0.35 | 隐藏 | 无 | 发解锁 RPC |
| 已解锁 | 原色 1.0 | 现有 | 有 | 打开空间（走 RPC，服务端已放行）|

- config 关时：全部月眼等同"已解锁"视觉，跳过所有灰黑/扫描逻辑
- netvar dirty 回调里统一调 `RefreshGemVisual()` 刷新 6 个月眼

### G. tooltip 随状态变化

- 未解锁：`手持/携带 X 月眼 左键扫描解锁`（带图标）
- 已解锁：现有 `左键打开/右键移动/中键复原`
- 需给宝石单独 tooltip（当前宝石 SetClickable(false) 无 tooltip）——可在 wheel 上加透明抓取层或设 tooltip

## 实现步骤（确认后执行）

1. modinfo 加 `moon_eye_unlock` 配置（默认 true）
2. modmain 服务端：UNLOCK_DATA + 序列化/存盘/加载（照抄 REVEALED）+ KEY_TO_PREFAB 对照
3. `TogglePocketDimensionChest` 开头加功能锁 + 说话提示
4. 加 RPC "unlock"：服务端验证持有 → 解锁 + 存盘 + 更新 netvar
5. player_classified 挂 net_string + dirty 同步
6. 客户端 widget：RefreshGemVisual + 灰黑态 + 未解锁点击发 RPC + tooltip 变化
7. 静态检查 + 升版本（三段式）

## 风险与注意

- **服务端验证持有**：遍历背包槽位需注意 overflow 容器（背包可能有 Merchant/背包中背包），简单起见先查主背包 + 手持
- **netvar 时机**：玩家进入游戏时 classified 的 netvar 要初始化（服务端在 playerpostinit 或 classified 初始化时 set 一次）
- **中英文说话**：`GetDisplayName()` 依赖客户端语言？——在服务端 SpawnPrefab 拿显示名可能返回服务端语言（英文）。⚠️ **需验证**：若服务端取的是英文名，中文玩家会看到英文。备选方案：用 `STRINGS.NAMES.BLUEMOONYE` 按客户端语言取（需 RPC 到客户端拼好再 Say，或服务端用 `TheNet:GetLanguage()` 判断）——实现时先测这一点
- **灰黑 tint**：0.35 够明显区分，但月眼贴图本身深色，可考虑 0.3 或叠暗层
- **配置关闭兼容性**：config 关时所有解锁相关代码短路，行为与升级前完全一致
