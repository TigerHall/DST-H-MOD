## hslot 蓝眼空间改为「数据仓库」方案（期1 完成）

### 架构决策
把蓝眼 160 格真实容器改成**纯数据记录**（物品脱离世界实体），UI 沿用简易存储同款。
两半互补：
- **unwrappable** 给序列化闭环：`GetPersistData()` → 数组存 → `SpawnPrefab` + `SetPersistData` 还原
- **简易存储** 给显示/交互：`FakeContainer`/`FakeItem` 把服务端 Lua 表伪装成容器，UI 走 `SendModRPCToServer`

关键发现：现有 `hslot_vault_list.lua` 已经有简存的三件套（分层缩放 / `TrueScrollList` 虚拟滚动 / 官方 `InvSlot` 交互），
**不用搬简存 2670 行 UI**。真正要换的只有两处：
1. `hslot_vault_list.lua:999 RefreshData` 的数据源（`container:GetItems()` → 数据快照）
2. `InvSlot` 的 `container` 参数（真实容器 → 单个 fake container）

### 源码事实（已核对）
- `unwrappable.lua:47-70` `WrapItems` 无任何容量字段，`itemdata` 纯 Lua 数组
- `unwrappable.lua:182-199` `OnSave` 直接 `return {items = itemdata}`
- `unwrappable.lua:117-131` `SpawnPrefab(prefab, skinname, skin_id)` + `SetPersistData` + `inventoryitem:OnDropped(true,.5)`
- ⚠️ `WrapItems` 只接 `local data = item:GetSaveRecord()`，**丢掉了第二返回值 references**（跨实体 GUID 引用）
- `perishable:OnSave`（perishable.lua:331）存 `perishremainingtime` 剩余量 → 物品不在世界就不 tick → **仓库天然保鲜**
- `stackable:OnSave`（stackable.lua:88）只在 `stacksize ~= 1` 才存 `{stack=n}`；上限 `MAXUINT`
- `EntityScript:GetSaveRecord`（entityscript.lua:248）带 `x/z` 坐标，物品不在世界时是死数据
- 简存 `terminalwidget.lua:680-826`：整个网格只消费扁平数组 `griddata`，每项 `{container, slot, item, overridequantity}`
- 简存真虚拟化：`terminalscrolllist.lua` 的 `create_widgets_fn` 只建 `num_visible_rows` 行，`update_fn` 复用填充
- 简存伪造制作材料：`hook.lua:426-461`，`inventory.fake_opencontainers` + hook 5 个函数
  （`FindCraftingItems` / `GetCraftingIngredient` / `GetItemByName` / `RemoveItem` / `Has`），调用前塞进 `opencontainers`，返回后 `shallowcopy` 还原
- 简存持久化：`PersistentData:Save` → `SavePersistentString(key, json.encode(t), ENCODE_SAVES)`，读用 `TheSim:GetPersistentString(key, cb, false)`
- `ENCODE_SAVES = BRANCH ~= "dev"`（main.lua:62），正式版存档走 zip，重复 prefab 名压缩率极高

### 踩坑（本次新发现）
1. **`item.components.inventoryitem.canbepickedup` 不是所有物品都有**，写成 `not xxx` 会拒绝所有正常物品，必须 `== false`
2. **`stackable.maxsize` 可能是 `math.huge`**，`json.encode` 编码不了 → 转 `"inf"` 字符串
3. **`Store.Get` 要检测 `_world ~= TheWorld`**：回滚/换存档时 modmain 不重跑，缓存会读到上个世界状态
4. **console 里 `ThePlayer` 是客户端实体，没有 `components`**；服务端玩家实体要 `AllPlayers[ThePlayer.userid]`
5. **迁移必须先收集数组再逐个 `Remove`**，边遍历 slot 边移除会让 container 内部 netvar/slots 表迭代中途变动
6. **`GetSaveRecord` 返回 `(record, references)` 两个值**，references 是跨实体 GUID 引用（`LoadPostPass` 阶段才解析），丢弃会悄悄坏掉绑定关系的物品

### 本次踩到的坑（都已修）
1. **`local function X` 定义在 `AddGamePostInit` 之后** → 闭包编译成全局访问，运行时 nil，迁移静默失败。必须前向声明 `local HSpaceMigrate` 且放在闭包创建之前
2. **`self._UpdateCell` 传给 TrueScrollList** → Lua 不自动绑定，调用时 context 顶替 self，参数全错位。必须传闭包
3. **`Widget.OnDestroy` 不存在**（widget.lua 只有 Kill/KillAllChildren），调了必崩
4. **`Widget:Kill()` 不触发 OnDestroy** → 注册关系手动断
5. **`SplitStack` 返回值不能提前 `:Remove()`**，AddItem 内部会 Remove，早删=凭空销毁
6. **`HSlotVaultList` 里的 `IsCraftingMenuOpen` 不存在**，正确的是 `hud:IsCraftingOpen()`
7. **`do ... end` 独立块** 被 lua_block_check 漏算 → 已修检查脚本（for/while 的 do 不重复计）
8. **未 Load 的库 `ready=false`** → `WhenReady` 队列永不执行，面板全白且无报错。`Store.Get` 里补自动 Load
9. **`require` 加载的模块不在 modmain env**，`AddModRPCHandler` 等包装函数不可见 → 改成 rpc.lua 只导出 handler，modmain 注册
10. **四色月眼走新面板会拉到未注册的空库** → 用 `theme.key` 分流

## v3.8.15：修崩溃（mod 加载期语法错误）

### 现象
开游戏直接崩，client_log 94KB 就断，生成 dmp。

### 根因
```
error loading module 'hspace/datastore' from file '../mods/hslot\scripts\hspace\datastore.lua':
  [string "..."]:141: function arguments expected near '~='
```
`datastore.lua` 里写成了：
```lua
recharge:GetRechargeTime ~= nil   -- ❌ 冒号后强制要参数列表
recharge.GetRechargeTime ~= nil   -- ✅ 判空必须用点
```
冒号是**方法调用**语法糖，后面必须跟 `(`，跟比较运算符会直接语法错。

### 崩溃链路
```
modmain.lua:1512  require("widgets/hspace_panel")
  → hspace_panel.lua:22   require("widgets/hspace_invslot")
  → hspace_invslot.lua:27 require("hspace/rpc")
  → hspace/rpc.lua:20     require("hspace/datastore")
  → 语法错误 → Disabling hslot → Reset() → dmp
```
⚠️ 只有 hslot 报错，其他 mod 正常（grep 全日志确认）。

### 工具补强
`lua_block_check.py` 原来只查块配平 + 括号，**查不出这一类**。已加规则：
冒号后必须是 `(` / `"` / `'` / `{`，否则报「冒号后不是方法调用」。
⚠️ 写正则时注意回溯：`:\s*(\w*)\s*([^\s(])` 会因为 `\w*` 回溯把 `gmatch(` 拆成 `gmatc`+`h`，
产生大量误报。改成先匹配名字、再手动看后续字符。

### 顺带发现
Steam 在 20:19 对 DST 做过一次创意工坊更新（`3475 updated, 3477 deleted files`），
`state changed : Fully Installed`。若玩家反馈缺 mod，先查
`steamapps/workshop/content/322330` 是否被清空。

## v3.8.16：蓝眼空间三个运行时 bug

### 1. `TheSim:EncodeAndZipString` 不存在
```
[rpc.push] 压缩失败: rpc.lua:63: attempt to call method 'EncodeAndZipString' (a nil value)
```
DST 只有**全局函数** `ZipAndEncodeString` / `DecodeAndUnzipString`
（官方用法：`chathistory.lua:324`、`components/undertile.lua:62`）。
`TheSim:EncodeAndZipString` 是我凭印象写的，根本不存在。
⚠️ 调不存在的方法只得到 nil，报错文本很像"数据问题"，容易误判。

### 2. `Widget:GetWorldPosition()` 返回 Vector3，不是三个数字
```
vector3.lua:14: attempt to index local 'self' (a number value)   self = 868
```
`widgets/widget.lua:336-338` 明确 `return Vector3(...)`。
写成 `local x,y,z = self:GetWorldPosition()` → x 是 Vector3、y 是 nil，
`mouse.x - x` 触发 `Vector3.__sub`，self 变成数字 868（鼠标 x 坐标）。
旧 `hslot_vault_list.lua:748-778` 注释里**早就记过这个坑**，我在新 panel 里又犯一遍。
修法：沿用旧文件的 `GetMouseLocalPos`（含锚点换算）。

### 3. "写盘失败" 是误报
```
[store.flush] 写盘失败: hslot_space_hslot
```
`mainfunctions.lua:18-31`：`TheFrontEnd` 存在时（单机/客户端）
`SavePersistentString` 会把回调再包一层，调用 `callback()` **不传 success**。
所以 `if not success` 每次都成立。必须判 `success == false`。

### 核心事实
- `Widget:OnControl(control, down)` → `CONTROL_*`（0~200）
  常用：PRIMARY 0 / SECONDARY 1 / ACCEPT 29 / CANCEL 30 / SCROLLBACK 31 / SCROLLFWD 32
  / FORCE_TRADE 40(Ctrl) / FORCE_STACK 41(Shift)
  ⚠️ **没有 CONTROL_MIDDLE**（constants.lua 里 0 个匹配）
- `TheInput:AddMouseButtonHandler(fn(button, down))` → `MOUSEBUTTON_*`
  LEFT 1000 / RIGHT 1001 / MIDDLE 1002 / SCROLLUP 1003 / SCROLLDOWN 1004
  ⚠️ 全局注册，OnDestroy 必须 `:Remove()`
- `CONTROL_SCROLLBACK/FWD`（滚动动作）≠ `MOUSEBUTTON_SCROLLUP/DOWN`（物理滚轮）
  TrueScrollList 用的是前者

### 教训（比知识点更重要）
重写整个文件时丢了三样"只有调用链才能发现"的东西：
1. `GetMouseLocalPos` 函数整个消失，但 `GetMouseLocal` 还在调它
2. `self:StartUpdating()` 没了 → OnUpdate 永不触发 → 拖动失效
3. `_mousebtn:Remove()` 没清理 → 关面板后右键还在响应
**以后大改文件，先 diff 旧版确认没有功能被静默删除。**
