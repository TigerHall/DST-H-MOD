### 格子优化月眼传送过场修正（19:3）—— 弃用 pocketwatch_warpback
- 用户反馈：传送时有"复用的声音"和"很多特效"，但勋章时空符文看起来干净、无声音
- 排查结论：**pocketwatch_warpback 状态图本身是硬编码脏的**（SGwilson.lua）：
  - `onenter` `SpawnPrefab("pocketwatch_warpback_fx")` 怀表特效
  - `pocketwatch_warpback_pst.onenter` `SpawnPrefab("pocketwatch_warpbackout_fx")` 出口特效
  - `pocketwatch_warpback_pst` timeline `SoundEmitter:PlaySound("wanda2/characters/wanda/watch/recall")` **这就是"复用的声音"**，且每次传送必播
  - 渐隐 `ScreenFade` 仅在距离 >30 触发
- **勋章时空符文其实也用同一个状态图**（medal_delivery.lua:276 `GoToState("pocketwatch_warpback",...)`），所以它也有 wanda 特效+声音；用户觉得"干净"是因它是消耗品/近距离用完即毁、未留意
- 结论：pocketwatch_warpback **无法做到"只渐隐"**，渐隐/怀表特效/声音被绑死。不能用它做过场
- 最终方案（格子优化 modmain.lua ~889-957、~990-1002）：
  - 服务端 RPC 直接 `player.Physics:Teleport`，不再进状态图

  - 客户端 `AddClientModRPCHandler("hslot_mooneye","teleport_done", fn)` 收到后 `ThePlayer:ScreenFade(true, 0.4)` 渐显

- **失效真因（关键坑）**：20:09 的 hook 用 `inv:EquipHasTag("htree_cowboy")` 在客户端判定，而 `replica.inventory:EquipHasTag`（inventory_replica.lua:248）在客户端走 `self.classified:GetEquips()` 分支，靠**服务端同步来的 tag** 判断。自定义 tag（`htree_cowboy` 等）经此同步到客户端副本时不可靠 → `EquipHasTag` 返回 false → hook 不拦截 → 黑边照旧。

- **通用结论（可入踩坑库）**：DST 客户端想判断"是否装备某类物品"来改 UI，**不要用自定义 tag + `EquipHasTag`**（replica 走 classified 同步，自定义 tag 不可靠）；优先用 prefab 名 / 官方自带同步标签 / `replica.inventoryitem` 上的已知字段。

  - **防风沙（沙暴免疫）= `playervision:ForceGoggleVision(true)`，位置 `水中木优化/modmain.lua:266`**，在 `SetHatNightVision` 里（夜视开关时调用）。该函数照搬自勋章 `ommateum_certificate`（`参考MOD/能力勋章 1909182187/scripts/medal_hook.lua:756` 同为 `ForceGoggleVision(true)` + `PushForcedNightVision(...)`，:759 为 `(false)` + `PopForcedNightVision`）。
  - `PushForcedNightVision("htree_nightvision", ...)`（267 行）是纯夜视（colour cube），不触发边框——这部分确实来自 ommateum 参考。
- **关键反转**：20:49 节结论"黑边就是 NutrientsOver"是**不完整**的。用户戴帽实际看到的四角黑边是 **`GogglesOver`**（`widgets/gogglesover.lua:22` 监听 `gogglevision` 事件 → `ToggleGoggles(true)` → 显示 `images/fx3.xml` 的 `goggle_over.tex`）。触发链：
  - `ForceGoggleVision(true)`（playervision.lua:285）→ 值变化时 `PushEvent("gogglevision",{enabled=true})`（:289）→ GogglesOver 监听 → 显示四角黑边。
  - 即：**防风沙能力和四角黑边是同一个 `ForceGoggleVision(true)` 的"一因两果"**。黑边是「防风沙」的副作用，绝不能删 `ForceGoggleVision` 这行，只能隐藏边框视觉。
  - NutrientsOver 只是 nutrientsgoggleshat 的次要边框，不是用户主诉的黑边。
