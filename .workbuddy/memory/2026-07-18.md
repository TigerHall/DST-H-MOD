### 格子优化月眼传送过场修正（19:3）—— 弃用 pocketwatch_warpback
- 用户反馈：传送时有"复用的声音"和"很多特效"，但勋章时空符文看起来干净、无声音
- 排查结论：**pocketwatch_warpback 状态图本身是硬编码脏的**（SGwilson.lua）：
  - `onenter` `SpawnPrefab("pocketwatch_warpback_fx")` 怀表特效
  - `pocketwatch_warpback_pst.onenter` `SpawnPrefab("pocketwatch_warpbackout_fx")` 出口特效
  - `pocketwatch_warpback_pst` timeline `SoundEmitter:PlaySound("wanda2/characters/wanda/watch/recall")` **这就是"复用的声音"**，且每次传送必播
  - 渐隐 `ScreenFade` 仅在距离 >30 触发
- **勋章时空符文其实也用同一个状态图**（medal_delivery.lua:276 `GoToState("pocketwatch_warpback",...)`），所以它也有 wanda 特效+声音；用户觉得"干净"是因它是消耗品/近距离用完即毁、未留意
- 结论：pocketwatch_warpback **无法做到"只渐隐"**，渐隐/怀表特效/声音被绑死。不能用它做过场
- 最终方案（格子优化 modmain.lua ~889-957、~990-1002）：
  - 服务端 RPC 直接 `player.Physics:Teleport`，不再进状态图

  - 客户端 `AddClientModRPCHandler("hslot_mooneye","teleport_done", fn)` 收到后 `ThePlayer:ScreenFade(true, 0.4)` 渐显

- **失效真因（关键坑）**：20:09 的 hook 用 `inv:EquipHasTag("htree_cowboy")` 在客户端判定，而 `replica.inventory:EquipHasTag`（inventory_replica.lua:248）在客户端走 `self.classified:GetEquips()` 分支，靠**服务端同步来的 tag** 判断。自定义 tag（`htree_cowboy` 等）经此同步到客户端副本时不可靠 → `EquipHasTag` 返回 false → hook 不拦截 → 黑边照旧。

- **通用结论（可入踩坑库）**：DST 客户端想判断"是否装备某类物品"来改 UI，**不要用自定义 tag + `EquipHasTag`**（replica 走 classified 同步，自定义 tag 不可靠）；优先用 prefab 名 / 官方自带同步标签 / `replica.inventoryitem` 上的已知字段。

### BUG 修复：鱼箱分页 table overflow 崩溃 → 移除分页功能（22:36）
- **现象**：进服/读档时 `LUA ERROR ... =[C] in function 'insert' ... modmain.lua(1380,1) table overflow`，发生在 `SpawnPrefab`→`mods.lua`→mod 加载链，卡在世界初始化。
- **根因**：world PostInit 里扩张鱼箱 slotpos 的循环：
  ```lua
  local base = p.widget.slotpos          -- base 与 p.widget.slotpos 是同一张表（引用）
  for page = 2, 3 do
    for _, v in ipairs(base) do          -- 边遍历边往同一张表 insert
      table.insert(p.widget.slotpos, v)  -- 表无限增长，ipairs 永不遇到 nil → 死循环 → table overflow
    end
  end
  ```
- **用户决策**：分页不好做就去掉。遂**彻底移除分页功能**，鱼箱回归单页 20 格（与最初一致），改动：
  - `modmain.lua` world PostInit：删掉 `colormooneye_toggle` 守卫下的 slotpos 扩张整块（`containers.require` 及双层循环）。
  - `modmain.lua` 客户端 `containerwidget` Open hook：删 `ApplyFishPages`/`FISH_PAGESIZE`/`_fish_prev`/`_fish_next` 箭头逻辑，仅留绿眼/红眼按钮字体放大。
  - `hslot_container.lua`：清掉"多页"相关注释，MakeFishParams 本就是单页 20 格填充，代码不变。
  - `modinfo.lua`：version 3.3 → **3.4**（此前 3.4 未落盘，借此次变更正式升版）。
- **结论**：鱼箱（紫/橙/黄）仍为各自独立 20 格单页容器，照常生成；崩溃消除。
- 后续若真要"一个容器多格"，正确做法应是预先算好完整 slotpos 表再一次性赋值，**绝不能在 ipairs 同一张表时往里 insert**。

## 源码研究：制图桌擦除 & 陶轮草图持久化（22:5x）

### 用户问题
制图桌怎么擦蓝图/草图广告；陶轮塞草图怎么出雕塑、怎么跨存档记住；想让制图桌记住擦过的纸、用两张纸兑换，能否实现。

### 制图桌擦除机制（cartography_prototyper.lua = prefab "cartographydesk"）
- 桌子只挂 `papereraser` 组件（纯标签+`DoErase` 转发）。真正逻辑在**纸自己**的 `erasablepaper` 组件。
- 动作 `ERASE_PAPER`（actions.lua:455/3880）：RMB 把纸（invobject，需 `erasablepaper`）放到桌子（target，需 `papereraser`）→ 调 `papereraser:DoErase(paper,doer)` → 转 `paper.components.erasablepaper:DoErase(eraser,doer)`。
- `erasablepaper:DoErase`（components/erasablepaper.lua）：把 paper `Remove()`，SpawnPrefab(`self.erased_prefab`，默认 `papyrus`) 还给玩家。**所以擦除=变回 papyrus**。
- **所有带 `erasablepaper` 的纸都能擦**（grep 全列表）：blueprint(蓝图)、sketch(草图)、cookingrecipecard(烹调节目卡)、mapscroll(地图卷轴)、scrapbook_notes/page(剪贴簿)、tacklesketch(钓具草图)、yotb_blueprints(YOTB草图)、battlesongs(战斗之歌)、stash_map(藏宝图)、temp_beta_msg(临时beta公告=“广告”)。"草图广告"≈ sketch + temp_beta_msg。
- 注意：擦除时 paper 已被 Remove，**要记录擦了什么必须在调原 DoErase 前先读 `paper.prefab`**。

### 陶轮出雕塑 + 记草图（sculptingtable.lua）
- `trader` 组件：`ongivenitem` 里 `if item:HasTag("sketch")` → `AddSketch` → `craftingstation:LearnItem(sketch:GetSpecificSketchPrefab(), sketch:GetRecipeName())`。
- `sketch.lua` 的 `GetSpecificSketchPrefab`/`GetRecipeName` 从 `SKETCHES` 表查对应 `chesspiece_xxx_sketch` / `chesspiece_xxx_builder` recipe。学会后陶轮 prototyper 树解锁对应雕塑配方，玩家用大理石/月石 sculpt。
- **跨存档记住草图的关键**：`craftingstation` 组件自带 `OnSave`/`OnLoad`，把 `self.items`/`self.recipes` 表写进存档（components/craftingstation.lua:86-104）。sculptingtable.lua 自己的 onsave 只存当前 pickable 的 sculptable 材料；草图记忆是 craftingstation 自动持久化的。陶轮被烧/拆 → `ForgetAllItems` 丢失。

### 用户想法（制图桌记擦除+两张纸兑换）可行性：完全可行
- 标准范式 = craftingstation 的 OnSave/OnLoad 持久化表。对 cartographydesk 用 `AddPrefabPostInit` 挂 `inst.erased_log = {}`(prefab→次数)，扩展现有 `inst.OnSave/OnLoad` 合并写入（不能覆盖原 onsave 的 burnt 字段）。
- Hook `inst.components.papereraser.DoErase`：先取 `paper.prefab` 再调原逻辑，成功 `erased_log[prefab] = +1`。
- 兑换：给桌子加 `trader` 组件（仿 sculptingtable），接受 2× papyrus（或桌子累积擦除额度）给奖励。纯服务端逻辑，`TheNet:IsDedicated()` 安全。
- ⚠️ 坑：paper 在 DoErase 内被 Remove，取 prefab 必须在调原逻辑前；`AddPrefabPostInit` 内逻辑要 `if not TheWorld.ismastersim then return end`；扩展 OnSave 别覆盖原 burnt 保存。

## 新建模块：制图桌回收（22:5x）

### 需求（用户拍板）
擦除带 `erasablepaper` 的纸（蓝图/草图/广告等）后，**全服共享**记住该纸，靠近任意制图桌可在制作菜单**无限重制**（花 N 张 papyrus）。类似陶轮学草图出雕塑。

### 落地产物（`制图桌回收/`）
- `modinfo.lua`：version 1.0，`all_clients_require_mod=true`，配置项 `enabled`(Boolean) + `papyrus_cost`(1/2/3，默认2)。
- `modmain.lua`：核心逻辑。
- `scripts/components/erasedlibrary.lua`：挂在 TheWorld 的全服记忆组件（OnSave/OnLoad）。

### 架构（完全照搬陶轮 craftingstation + TECH.LOST 门控）
1. 预先为每种可擦纸建一条 `AddRecipe2("reissue_"..prefab, {Ingredient("papyrus",cost)}, TECH.LOST, {nounlock=true, product=prefab, no_deconstruction=true})`——平时"锁定"，只有附近 craftingstation 记住它才可做（builder.lua:975 `craftingstation:KnowsRecipe` 门控）。
2. TheWorld 挂 `erasedlibrary` 组件，存 `erased_items` 集合（具体 prefab）。
3. 每张制图桌服务端加 `craftingstation`（`nosave=true`）；`prototyper.onturnon` 时把全局库 `ForgetAllItems`+`LearnItem(p,"reissue_"..p)` 同步进本桌；`onturnoff` 清空。
4. Hook `papereraser:DoErase`：调原逻辑前取 `paper.prefab`；草图用 `paper:GetSpecificSketchPrefab()` 取具体 `chesspiece_xxx_sketch`（因 `SetPrefabName("sketch")` 使 `paper.prefab` 恒为 "sketch"）；记进 `erasedlibrary`。

### 关键结论（已核实源码）
- 陶轮雕塑配方用 `TECH.LOST + nounlock`，靠附近 `craftingstation:KnowsRecipe` 解锁（builder.lua:277/671/975）。本方完全复用此机制。
- 配方可用性由**服务端** builder 决定，客户端经 `builder_replica` 同步 → craftingstation 只需加服务端（验证：`builder_replica:KnowsRecipe` 转发真实 builder；prototyper/craftingstation 无 net 复制）。
- 草图无自定义 image 时实际库存图标是 `sketch.tex`（sketch.lua ChangeImageName 仅在有 image 字段时改），配方 `image` 须用 `v.image or "sketch"` 否则缺图标。
- 未做运行时实测（无游戏环境），建议本地联机验证擦除→点亮→重制闭环。
