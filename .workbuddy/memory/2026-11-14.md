## 行走手杖优化 v5.5：掌掴击退（仿 handpillow_steelwool）

### 需求
伤害与位面伤害都为 0 时，手杖变成"钢棉枕头"：有前摇、打不痛、能击飞所有可攻击目标（不限兔人/玩家），参考 bearger 的 knockback。

### 官方实现链路（重要参考）
- `prefabs/pillow_defs.lua`：steelwool = `strengthmult 2.2` / `laglength 0.20`
- `prefabs/pillow_equipment.lua`：
  - `weapon:SetDamage(TUNING.PILLOW_DAMAGE)`（=0）、`weapon:SetRange(TUNING.DEFAULT_ATTACK_RANGE, TUNING.PILLOW_HIT_RANGE)`（=2, 2.5）
  - `inst._laglength / _knockback(0.1) / _strengthmult`，加 `pillow` + `propweapon` 标签
- `stategraphs/SGwilson.lua:1346`：`ActionHandler(ACTIONS.ATTACK)` 里 `weapon:HasTag("pillow") → "attack_pillow_pre"`；该 state `SetTimeout(pillow._laglength)` 即前摇，之后 `attack_pillow` 的 `TimeEvent(FRAMES)` 里 `PerformBufferedAction()`
- `prefabs/pillow_common.lua`：`DoKnockback` = NOPUSH_TAGS(`epic`,`nopush`) 过滤 + 身体护具 `_defense_amount` 减伤 + `PushEvent("knockback", {knocker, radius, strengthmult, forcelanded})`
- `SGbearger.lua:180`：对 `_combat` 目标直接 `PushEvent("knockback")`，这就是"通用击退"的做法

### 关键事实（踩坑）
- **knockback 事件只有少数状态图有处理**：SGwilson / SGghost / SGchester / SGcozy_bunnyman / SGpigelite / SGwx78_possessedbody。普通生物（SGpig/SGhound/SGspider/SGrabbit…）**没有 knockback state**，所以 bearger 的击退对它们其实无效（只掉血不飞）
- 玩家 knockback 位移公式：`speed = strengthmult * 12 * k`，`k = .3*distsq/rangesq - 1`（恒负，[-1,-0.7]），onupdate 里每帧 `+0.075` 衰减
- `_laglength` 是普通 Lua 字段，**不会网络同步** → 客户端预测的 `attack_pillow_pre` 需要客户端自己也赋值，所以 `AddPrefabPostInit` 里要在 `TheWorld.ismastersim` 判断**之前**设置
- `Combat:CalcDamage` 中 weapon 存在时直接用 weapon 伤害，0 不会 fallback 到 defaultdamage（所以 damage=0 安全）
- 力度换算：mob 物理推用 `strengthmult * 8.4`（= 12 * 0.7），0.3 秒 ≈ 5.5 格

### 本次实现
- `modmain.lua`：新增 `PILLOW_KNOCKBACK` 常量表 + `DoPillowKnockback(attacker, target)`
  - 主路径：标准 `PushEvent("knockback")`（对玩家/鬼魂/chester/兔人生效）
  - 兜底：目标 `sg.states.knockback == nil` 时，短促 `Physics:SetMotorVel` 推 0.3 秒（每 tick 检查 `Map:IsPassableAtPoint`），字段 `_hpillow_push_task` 防叠加
  - `pillow` 标签 + `_laglength = 0.16` 双端设置；`range_attack > 0` 用配置范围，`== 0` 时用官方 `DEFAULT_ATTACK_RANGE / PILLOW_HIT_RANGE`（2 / 2.5）
  - 掌掴模式下强制跳过 `extra_damage`（越战越强会把 0 伤害叠成正数）
- `modinfo.lua` v5.4 → v5.5：`damage_value` 新增 "0" 选项且默认 0；`planardamage` 默认 0；`rain/lightning/constant_temp` 默认 false

### v5.6 参数调整 + 群攻击退
- `PILLOW_KNOCKBACK`：laglength 0.16 / knockback 0.16 / strengthmult 3.6（去掉了 `hit_range` 字段，改跟随远程攻击配置）

## hcane v5.9：击退重做 + 自动拾取进月眼空间

### 击退为什么之前无效 / 乱飘（根因）
- **minotaur 这类 boss 推不动**：`MakeGiantCharacterPhysics(inst, 1000, r)` → `Physics:GetMass() = 1000`，被 v5.6 加的 `PILLOW_MAX_PUSH_MASS = 999` 阈值挡掉；另外 collision group 是 `COLLISION.GIANTS`，motor vel 推力该组吃得很死
- **warglet / shadow_rook 乱飘**：`Physics:SetMotorVel` 是**实体局部坐标系**（x = 面朝方向），我只在开始时 SetRotation 一次，之后 brain 让它转向（追击/逃跑），motor vel 方向就跟着转 → 在 0.3 秒内方向随机抖动。warglet `MakeCharacterPhysics(inst, 10, .5)`、rook `MakeCharacterPhysics(inst, 50, 1.5)` 质量都不大，但都频繁改朝向
- 官方 `knockback` 状态图只有 6 种（SGwilson / SGghost / SGchester / SGcozy_bunnyman / SGpigelite / SGwx78_possessedbody），其余实体的 PushEvent 只重置受击硬直，位置不动

### 新实现
- 删掉 `PILLOW_MAX_PUSH_MASS` 质量阈值
- 兜底位移改成「沿远离攻击者的世界方向逐步 Teleport」：`strengthmult * 2.4` 总距离（3.6 → 8.6 格），`DoPeriodicTask(0.05)` 每步 0.5 格（约 10 格/秒），逐步 `Map:IsPassableAtPoint` 检查，撞墙/水边即停
- 与朝向、质量都无关，所以 boss 也能推，方向不会乱

### 自动拾取进月眼空间- 格子优化的口袋空间容器统一打 `pocketdimension_container` 标签（hslot_container.lua:111），hcane 用 FindEntities 按标签探测，不写死 prefab/key
- `GetOpenPocketContainer(doer, prefab)`：先找 `container:IsOpenedBy(doer)` 的容器，**优先返回里面已有同类物品的那个**（`container:Has(prefab, 1)`），否则返回第一个打开的
- 容器缓存 + 空结果 2 秒节流，避免每次拾取全场扫
- 拾取优先级：已触发陷阱 → 收获；否则 ① 打开的口袋空间（`CanAcceptCount > 0` 且 `GiveItem ~= nil`）② 玩家物品栏
- 顺带发现 `hslot_container.lua` 末尾的 `return` 后面接 `MakePocketContainer(...), ...` 其实是合法的**多返回值 return**，不是死代码 —— 4 个容器 prefab 都正常注册

## hcane v6.0：修卡顿（Teleport → SetVel）

### 卡顿根因（两个）
1. **`Physics:Teleport` 每 0.05 秒一次**：20 次/秒/目标，每次触发电块变更、碰撞体重建、位置网络同步；群攻 20 个目标 = 400 次/秒 → 服务器和客户端一起卡

- 击退改用 **`Physics:SetVel(x, y, z)`（世界坐标系速度）**：

  - `MakeCharacterPhysics` 自带 `phys:SetDamping(5)`（standardcomponents.lua:406），速度会自然衰减

## hcane v6.0.2：击退物理通道定案（三种方案全试过）

### 关键物理机制（重要，别再走弯路）
| 方案 | 结果 |
|---|---|
| `Physics:SetVel(x,y,z)` | **完全推不动**。SetVel 设的是「实际速度」，而 locomotor 每帧用 `SetMotorVel`（`SetMotorSpeed` → `SetMotorVel(speed,0,0)`，locomotor.lua:730）设「目标速度」，物理引擎每步把实际速度拉回 motor vel → 1~2 帧就被吃掉 |
| `Physics:Teleport` 每 0.05s | 能推，但每次重建碰撞体+同步位置，目标一多（群攻）就卡成 PPT |
| `Physics:SetMotorVel(v,0,0)` | ✅ 生物唯一有效的推力通道，但它是**实体局部坐标**（局部 +x = 面朝方向），目标一转身方向就跟着变 |

### 最终实现
- 每 0.05 秒：`locomotor:Stop()`（清掉 brain 的追击 dest，别和推力抢通道）+ `Transform:SetRotation(远离角)`（锁方向）+ `Physics:SetMotorVel(v, 0, 0)`
- 远离角 = `math.atan2(uz, ux) * 180 / math.pi`（与官方 `GetAngleToPoint` 同一套角度：rotation=0 → 前向 (1,0)）
- 初速 `strengthmult * 8.4`（3.6 → 30，v5.6 已验证手感），6 步线性降到 0（0.3 秒，位移约 4.5 格）
- 收尾 `Physics:Stop()` 清 motor vel，否则目标会一直保持末速度滑行
- 去掉了 mass 阈值（v5.6 推不动 minotaur 的真正原因：`MakeGiantCharacterPhysics(inst, 1000, r)` → mass 1000 被我设的 999 阈值挡掉，推力代码压根没执行）

### 未解决风险
- 若某个 boss 的 brain 每帧重设 dest，会与我们的 Stop/SetMotorVel 争通道，推力打折扣（但仍有位移）

## hcane v6.0.6：受击闪烁改成叠加白光 + 红白急闪

### 为什么从 SetMultColour 换成 SetAddColour
- `SetMultColour` 是**乘算**，会把实体本色压掉（冰冻蓝、月圆白都会被打回白，而且是不可逆的，AnimState 没有 GetMultColour）
- `SetAddColour(r, g, b, a)` 是**叠算**（鬼魂作祟/冰冻/高亮都用它），在原色上叠一层光，Pop 后自然消失
- 官方血量低/冰冻的用法：`FREEZE_COLOUR = { 82/255, 115/255, 124/255, 0 }`，第 4 个参数 a 固定填 0

### colouradder 叠加栈（重要）
- 实体若有 `colouradder` 组件，必须走 `PushColour(source, r,g,b,a)` / `PopColour(source)`，直接 SetAddColour 会和冰冻/高亮互相顶掉
- `colouradder.lua:84` 的 PushColour 用 `colourstack[source]` 做 key（**不是数组栈**），同一个 source 反复 Push 只更新不叠加，Pop 一次即清空 —— 所以逐拍改色是安全的
- 范式照抄 `freezable.lua:174` 的 PushColour/PopColour 分流写法

### 参数
- `FLICKER_STEP = 0.06`，`FLICKER_SWITCHES = 6`（≈0.36 秒 6 拍）
- `FLICKER_RED = {0.55, 0.04, 0.04}`、`FLICKER_WHITE = {0.40, 0.40, 0.40}`
- 奇数拍红、偶数拍白，立即先来一拍红（不等第一个 tick）

## hcane v6.0.7：击飞独立开关 + 配置归组
