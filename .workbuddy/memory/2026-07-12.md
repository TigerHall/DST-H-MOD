## widget=nil 崩溃的真正根因

`container_replica` 的 `Class` 定义：

```lua
Class(function(self, inst) ... end, nil, nil)  -- 第三个参数是 nil，没有数据代理！
```

`self.widget` 只是一个普通 Lua 字段，**不在数据代理系统中**。所以无论 `SetPristine` 之前还是之后设置 widget，client 端的 replica 都接收不到——widget 永远为 nil。

**最终修法**：`AddClassPostConstruct("widgets/containerwidget", ...)` 劫持 `Open`，在崩溃前从本地 `params` 补上 widget：

```lua
if rc and rc:GetWidget() == nil then
    local local_params = containers_mod.params[container.prefab]
    if local_params and local_params.widget then
        rc.widget = local_params.widget
        rc:SetNumSlots(#(local_params.widget.slotpos or {}))
    end
end
```

## 容器 SetPristine 时序修正（2026-07-12 15:30）

**发现问题**：官方模式（treasurechest/fish_box/棱镜）全是 `SetPristine → 客户端 return → 服务端加容器`。之前的两个修复（_ctor 修补 + 内联 widget）全是绕路，根因是**在 SetPristine 之前添加了容器组件**。

**正确顺序**：
```
SetPristine()
if not TheWorld.ismastersim then return end
inst:AddComponent("container")
inst.components.container:WidgetSetup("xxx")  -- 用注册名，不用内联 data 表
```

**额外发现**：客户端 `container_replica` 的构造器（line 47）自动调用 `containers.widgetsetup(self)` → 按 `self.inst.prefab` 查 `params`。所以必须在 `modmain.lua` 中注册 `containers.params.hsee = {...}`。

**文件修改**：
- `modmain.lua`：移除 _ctor 修补，改用 `containers.params.hsee` 注册容器参数
- `hsee.lua`：容器组件移到 SetPristine 之后的服务器端分支，`WidgetSetup("hsee")` 用注册名
- `modinfo.lua`：0.6.9 → 0.7.0
- `pitfalls.md`：新增 #34（container before SetPristine）+ #35（WidgetSetup 必须用字符串名）
