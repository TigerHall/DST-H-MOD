## 任务：三方容器/UI 设计对比研读（官方 cookbook / 我们 hslot / 简存）

### 核心结论
- **cookbook 页面不是容器**：`prefabs/cookbook.lua` 走 `simplebook.onreadfn → ShowPopUp(POPUPS.COOKBOOK)` →
  `CookbookPopupScreen(Class(Screen))` → `CookbookWidget`(tab) → `CrockpotPage`(ScrollingGrid 5×5 + Spinner 筛选/排序 + 详情面板)。
  数据源是全局 `TheCookbook`，无 slot、无 netvar、无 RPC。`containers.lua` 里 grep cookbook 零匹配。
- **三者滚动同源**：官方 cookbook 和我们 hslot 都用 `TEMPLATES.ScrollingGrid`（`templates.lua:1968`，内部 TrueScrollList，
  `ScrollWidgetsCtor` 建 `num_visible_rows+2` 行格子 + `Grid:FillGrid`）；简存 `terminalscrolllist.lua:10` 直接拷了官方 TrueScrollList 源码。
- **我们 hslot 路线**：真容器 + 静态抬 `MAXITEMSLOTS=160` + 劫持 `containerwidget.Open` 换 ScrollingGrid 列表，
  格子用官方 `InvSlot`（`hslot_vault_list.lua:308`），交互零 RPC，正确性最稳。
- **简存路线**：假容器/假物品 + metatable 伪装官方 replica 接口 + 13 个 ModRPC + JSON/zip 全量快照，
  按 prefab+skin 分组压缩展示。容量真相 = 聚合附近多个真箱子，随箱子数线性增长，不是单容器无限格。

### 关键坑（已验证）
- 绝不能 `self:Hide()` 官方 ContainerWidget：`inventory_replica.lua:349 GetOpenContainers()` 靠
  `widget.inst.entity:IsVisible()` 判断容器是否打开，藏了会导致 Shift+左键转移、制作材料识别全失效。
  正解 = 保可见 + 只藏内容（bgimage/bganim/button/inv）。

## 任务：官方容器加翻页的可行性（参考 MOD workshop-936440913）

- 结论：**可行，但与我们同源且更险**。该 MOD 与我们的扩格本质相同——都突破 `container_classified._itemspool`
  默认 20 个 net_entity 的限制：
  - 我们：启动时静态抬 `containers.MAXITEMSLOTS=160`
  - 它：hook `InitializeSlots`（`container_classified_patch.lua:653-700`），`slots = numslots × pagecount`（:665），
    运行时 `table.insert(inst._items, table.remove(inst._itemspool, 1))`（:693）动态扩池，等价机制。
- 它的翻页 = **服务端真实搬物品**（`pageable.lua:145 Move()`：循环移位 `thecontainer.slots` + 用
  `v:set_local(itemvalues[k]); v:set(itemvalues[k])` 改写 netvar），加 `net_byte("pagecount")` + `net_bool("ispaging")` 同步。
- UI：`AddClassPostConstruct("widgets/containerwidget")` 挂 `PageWidget`（左右箭头），保留官方网格布局。
- 代价：要打 700+ 行 classified 补丁（升级易碎），翻页时搬运真实物品多人易竞态，0.15s ispaging 锁。
- **决策**：不改我们现有方案。ScrollingGrid 滚动列表比"数据层翻页"更稳、代码更少、无搬运竞态。

- 现象：面板拖到右上角后，中键只有特定角落有反应，用户怀疑"负数问题"。
- 根因：**坐标语义混用**（v3.8.6 改 world_scale 时遗留）。`GetMouseLocal()` 已从「父级绝对坐标」
  改成「鼠标相对面板中心的偏移」(`m - GetWorldPosition`，面板中心=原点)，但
  `IsMouseOverPanel()` / `IsMouseOverGrid()` 仍做 `abs(loc.x - pos.x)`（pos=self:GetPosition）
  → 重复减位置。面板居中(pos≈0)碰巧对；拖到右上角(pos=+300,+200)后命中区整体推到左上。
- 修复：①两处命中判定直接用 `abs(loc.x)/abs(loc.y)`，删掉 `loc - pos`；
  ②中键复位从 `IsMouseOverPanel` 门禁里独立出来——面板开着 anywhere 按中键都回中心，
  不再依赖命中判定（右键拖动仍保留判定）。
- 版本 3.8.9 → 3.8.10，静态检查通过。踩坑库三份追加 #67 / #36 / #32。
- 教训：改坐标函数返回语义必须 grep 所有调用方；"面板开着就生效"的全局操作不要套命中门禁。
