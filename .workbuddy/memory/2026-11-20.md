## v3.8.3 后续：4K 仍小，通读 templates.lua + 加 scale 诊断

### 用户反馈
3.8.3（官方 ScrollingGrid + RectangleWindow 0.7）4K 下 hslot 仍很小；要求通读 templates.lua。

### templates.lua 通读发现
- 官方缩放有两种机制：
  1. `SetScaleMode(SCALEMODE_PROPORTIONAL)`（ScreenRoot/LeftSideBarBackground/_CreateBackgroundPlate 用，
     line 34/91/109）—— widget 自己按分辨率等比缩放。
  2. `GetHUDScale()` = HUD size 系数 × res_scale（frontend.lua:1233），
     res_scale = min(max(1,w/1920), max(1,h/1200))，**无上限**（4K≈1.8）。
- 官方专门有 `GetProportionalHUDScale()`（frontend.lua:1225，注释：父层已有 PROPORTIONAL 时用），
  不含分辨率缩放。
- RectangleWindow(templates.lua:1801) = NineSlice + 自带 SetScale(0.7,0.7)（1813），sizeY clamp 620。
  → 外框本身就带 0.7；简存与 hslot 现已一致（hslot 不再覆盖）。
- ScrollingGrid(templates.lua:1961) 内部 TrueScrollList + Grid:FillGrid，scissor 自动算。

### 关键推理链（排除法）
- 同屏并排时简存/官方/hslot 的 GetHUDScale 完全相同 → 4K 差异不可能来自 res_scale/GetHUDScale。
- 简存 ui.lua 与 hslot modmain 的 root 挂载逐行一致（containerroot.parent + GetHUDScale + hook）。
- 简存 RefreshWorldScale（967）只是拖动坐标换算，不影响大小。
- → 静态源码层面已完全一致，无法再推断；必须实测运行时 scale。

### 已加一次性诊断（modmain controls hook，2 秒后打印）
`[hslot][scale] screen=.. hudScale=.. propHUD=.. hslotRoot=.. termRoot=.. outerCR=.. innerCR=..`
用 GetLooseScale() 取数字（Vector3 坑）。诊断代码标了"抓完即可删"。
- 等用户重进游戏贴日志。判读：hslotRoot vs termRoot 是否相等；outerCR 是否 1.25 钳制。

## v3.8.4：找到 4K 偏小根因 —— 面板自设 MIDDLE 锚点（3.10 版本对照）

### 用户关键线索
"3.10 那一版本全部移植后，界面 UI 就是正常的" —— 直接用备份的 3.10 当正确答案对照。

### 诊断日志实测（client_log 00:07:47）
```
[hslot][scale] screen=3840x2160 hudScale=1.6650 propHUD=0.9250 hslotRoot=1.6650 termRoot=1.6650 outerCR=1.2500 innerCR=1.6650
```
→ hslotRoot == termRoot == 1.665，**root 层完全相同**，排除 GetHUDScale/res_scale/挂载差异。
→ 同屏并排时两者 hudScale 一致，4K 差异必在 widget 内部。

### 决定性差异（3.10 正常 vs 3.8.3 偏小）
逐行对比 hspace_panel（备份）与 hslot_vault_list：
- **3.10 hspace_panel 和简存 TerminalWidget 都完全不设 SetHAnchor/SetVAnchor**
- **当前 hslot 设了 `self:SetHAnchor(MIDDLE)` + `SetVAnchor(MIDDLE)`**（构造 401-402）
其余全一致（680×420 / gridroot 0.6 (0,-30) / 15×6 / RectangleWindow 官方 0.7 / 挂载 containerroot.parent+GetHUDScale / 创建挂载 Open 流程）。
→ 根因判定：子 widget 在带 SCALEMODE_PROPORTIONAL 的父层下再设 MIDDLE 锚点，
   4K 下缩放按不同基准计算 → 面板/格子偏小。

### 本次改动
1. `hslot_vault_list.lua`：删掉 `SetHAnchor(MIDDLE)/SetVAnchor(MIDDLE)` 调用；
   保留 `h_anchor/v_anchor` 字段仅供 GetMouseLocalPos 鼠标换算（不调 API）。
   ⚠️ 若面板跑位再议 —— 但父层 containerroot 自带 MIDDLE，(0,0) 仍居中，3.10 已验证。
2. `modmain.lua` 加两处诊断：
   - controls hook 2秒后 `[hslot][scale]`（已抓到数据，可删）
   - 面板打开 0.5秒后 `[hslot][size] frameWS=.. gridWS=.. termBgWS=..`（待抓，验证修复）
3. version 3.8.3 → 3.8.4。
