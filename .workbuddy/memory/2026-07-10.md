## 月眼地图传送 MOD（`月眼传送/`）

### 研究 vault_orb_refined 传送宝珠的地图点击传送机制

完整数据流涉及 **6 个文件**：
1. `vault_orb_refined.lua` (预制物) — 添加 `vaultorbteleporter` 组件，3 个回调
2. `vaultorbteleporter.lua` (组件) — StartMapAction / CancelMapAction / Activate
3. `vaultorbteleportdestination.lua` (目的地组件) — 创建限制性的 globalmapicon
4. `mapscreen.lua` — ProcessStaticDecorations_VaultOrbTeleporter 渲染地图标记
5. `actions.lua` — STARTVAULTORBTELEPORT + VAULTORBTELEPORT_MAP 两个动作
6. `componentactions.lua` — vaultorbteleporter 组件的动作注册

关键机制：
- `globalmapicon:TrackEntity(target, restriction, icon)` 的 restriction 参数控制可见性
- `bufferedmapaction` + `SetupMapAction` 将物品与地图动作绑定
- `maponly_checkvalidpos_fn` 在客户端/服务端均执行位置校验
- 通过 `pointspecialactionsfn` (playeractionpicker) 注册无手持物的地图原生动作
- `setowner` 事件在客户端也会触发，`OnSetOwner` 会在两端覆盖 `pointspecialactionsfn`

### 月眼实现方案（方案B实施）

直接在地图上点击月眼图标传送，无需手持月眼。

使用 MOD 开发的三层架构：
1. **`AddAction` 注册自定义 `MOONEYEMAPJUMP` 动作** — map_only, rmb, closes_map
2. **`AddPrefabPostInit` 给月眼加标签 + 标记地图图标** — 服务端 mooneye 标签, 客户端 mooneyedestination 标签
3. **`AddClassPostConstruct` hook playeractionpicker** — 通过 pointspecialactionsfn 注册地图动作

### 踩坑记录
- 地图动作必须用 `AddAction` API 注册（非直接 `ACTIONS.X = Action()`）
- `distsq` 不是全局函数，需手动计算 `dx*dx + dz*dz`
- 客户端 `ent._target` 不可用（`common_server` 不运行于客户端），改用 `ent:HasTag("mooneyedestination")` 判断
- `GlobalMapIconsDB.prefabs["globalmapicon"]` 为客户端全局变量，可直接遍历

### Fix: pointspecialactionsfn 被 OnSetOwner 覆盖
- `OnSetOwner` 通过 `"setowner"` 事件触发，**客户端也会触发**
- 所有角色的 `OnSetOwner` 都会设置 `pointspecialactionsfn`
- 用 `DoPeriodicTask(0)` 轮询等待，等角色设置完成后再包装，两端统一处理
